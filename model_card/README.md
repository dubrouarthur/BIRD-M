# BIRD-M v0.1 (pilot): enterprise assistant for French companies

**BIRD-M** is a LoRA fine-tune of [Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) aimed at the everyday tasks of French companies, in French and English: business emails, documents, slide decks (BIRD-Deck JSON), financial analysis, structured extraction and the **BIRD-M Skill Protocol (BSP)**. BSP lets a company plug in its own procedures ("skills") without retraining, routes to them with a single token and controls access.

> ⚠️ **Pilot release (v0.1).** This is the first training run, made on a small budget (≈ 6k examples, 1 epoch). It is published to share progress and the method, not as a production model. See _Limitations_.

## What is new

- **BIRD-M Skill Protocol.** 211 special tokens placed in Qwen3.8's unused padded embedding rows (ids 248077–248287), so the architecture is unchanged.
  - **Routing:** skills are bound in context to pointer slots. Routing is a constrained 1-token decision, auditable and maskable per user role.
  - **Loading:** a skill body is only loaded when the model invokes it.
  - **Reasoning budget:** set by the invoked skill (`compute: direct | short | full`).
  - Spec and reference implementation: [`docs/SKILL_PROTOCOL.md`](https://github.com/dubrouarthur/BIRD-M/blob/main/docs/SKILL_PROTOCOL.md).
- **BIRD-Deck.** A semantic slide format with 13 layouts, density limits and a validator. The model chooses the content and the layouts; the renderer owns the design.
- **Verifiable data.** BIRD-World fictional companies with coherent multi-year accounts, so every figure in the finance tasks has an exact ground truth.

Processing:

- French and English only.
- `<think>` blocks are removed from the targets (direct answers by default).
- Answers that mention other assistants or vendors are removed, to avoid identity contamination.
- Near-duplicate prompts are removed.
- Every record is checked by the BSP renderer.

Full details: [`docs/DATASETS.md`](https://github.com/dubrouarthur/BIRD-M/blob/main/docs/DATASETS.md).

## Training procedure

- **Method:** LoRA r=32, α=64, on every linear layer of the language model. The 211 BSP token rows are trained in full, in both `embed_tokens` and `lm_head`, because the embeddings are untied. The vision tower is not trained.
- **Optimiser:** 1 epoch, lr 1e-4 (BSP rows 1e-3), cosine schedule, ~16k tokens per step, bf16, gradient checkpointing.
- **Loss:** computed only on what the model must generate (routing decisions and answers). Injected skill bodies and prompts are masked.
- **Hardware:** 1× NVIDIA H200 (Hugging Face Jobs).

## Evaluation

`<RESULTS>`

BIRD-Bench uses **fictional companies and skills that are never seen during training**:

- skill routing on unseen skills, plus fresh episodes on seen skills;
- finance tasks scored with an exact numeric checker.

## How to use

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3.8-27B", dtype="bfloat16", device_map="auto")
tok = AutoTokenizer.from_pretrained("adubrou/BIRD-M")  # includes the 211 BSP tokens
model = PeftModel.from_pretrained(base, "adubrou/BIRD-M")
```

For skill routing, use `RoutingSession` from the reference implementation (`bird_m/skills`). It provides constrained decoding, the stable slot binding and the `logit_bias` that bans unbound slots.

## Limitations

- **Pilot scale:** ~6k examples and 1 epoch. Expect uneven quality, especially on tasks with little data such as meeting minutes, proofreading and FR↔EN translation.
- **Slides:** the converted OfficeSmith decks teach the BIRD-Deck _format_. High-quality storytelling decks are planned for v0.2, generated with the `bird-deck` skill and filtered by the renderer.
- **Tool calling:** not trained in this version, because the open datasets use a different tool-call format than Qwen3.8.
- **Finance:** the tasks use simplified French GAAP conventions, stated in the prompts. The model is not a substitute for an accountant.
- **Synthetic data:** synthetic sources may carry the biases of the models that generated them.
